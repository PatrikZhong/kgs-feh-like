 [DONE] Phase 0 — Project Bootstrap

 Goal: Working Godot 4 project committed to git.

 Steps:
 1. Create a Godot 4.x project in the repo root.
 2. Add a proper .gitignore for Godot (.godot/, *.import temp files, etc.).
 3. Set the main scene to a placeholder Main.tscn.
 4. Verify the project opens and runs a blank window.

 Critical files: project.godot, .gitignore

 [DONE] Phase 1 — Grid & Tile System

 Goal: A visible, navigable grid. Foundation of all gameplay.

 Steps:
 1. Create GridManager as a TileMapLayer node wrapping a TileSet.
 2. Define tile types as an enum: NORMAL, HIGH_GROUND, DANGEROUS, BLOCKED.
 3. Implement grid ↔ world coordinate helpers (grid_to_world(), world_to_grid()).
 4. Implement A* pathfinding using Godot's built-in AStarGrid2D, respecting blocked tiles.
 5. Highlight reachable tiles: pass a unit's position + movement range → return a Set of reachable cells.
 6. Implement tile highlight overlays (colored modulate on a separate TileMapLayer).

 Critical files:
 - scenes/battle/GridManager.tscn
 - scripts/battle/GridManager.gd

 [DONE] Phase 2 — Unit System

 Goal: Units exist on the grid with stats.

 Steps:
 1. Create UnitData as a Resource with fields: unit_name, class_type (enum), max_hp, attack, defense, move_range, attack_range.
 2. Create Unit.tscn (Node2D + Sprite2D + HealthBar + collision).
 3. Create Unit.gd with:
   - current_hp, has_moved, has_attacked flags
   - take_damage(amount) → emit died signal
   - snap_to_cell(cell: Vector2i) using grid-to-world conversion
 4. Define 4 unit classes via UnitData presets:
   - Knight: high HP/DEF, move 3, range 1
   - Cavalry: normal stats, move 5, can path through ally tiles (jump)
   - Archer: normal HP, low DEF, move 3, range 2
   - Mage: low HP, high ATK, move 3, range 2, board-modifying spells (stub for now)
 5. Create a BattleMap.gd that places units on cells at scene load.

 Critical files:
 - scenes/battle/Unit.tscn
 - scripts/battle/Unit.gd
 - resources/units/KnightData.tres, etc.

 [DONE] Phase 3 — Drag & Drop Input

 Goal: Player can pick up and place units. Must feel fluid.

 Steps:
 1. In BattleMap.gd, handle _input(event):
   - InputEventMouseButton PRESSED on a unit cell → begin drag, compute reachable cells, highlight them
   - InputEventMouseMotion → move a "ghost" sprite (the dragged unit) under the cursor
   - InputEventMouseButton RELEASED → if target cell is valid, commit move; else cancel
 2. Animate the unit snapping to the new cell using Tween (fast, ~0.1 s).
 3. Grey out units that have already moved this turn (has_moved = true).
 4. Ensure the ghost sprite renders above all other elements (use CanvasLayer or high z-index).

 Critical files:
 - scripts/battle/BattleMap.gd (input handling)
 - scripts/battle/Unit.gd (ghost/tween methods)

 [DONE] Phase 4 — Combat System

 Goal: Units attack each other. Fast resolution like FEH (attack + counterattack in one animation).

 Steps:
 1. After a unit moves onto an attack-range cell of an enemy, show an "Attack" confirmation (or auto-resolve if the design opts for auto).
 2. CombatResolver.gd (autoload or static class):
   - resolve(attacker: Unit, defender: Unit) -> void
   - Attacker deals attacker.attack - defender.defense damage (min 1)
   - If defender is in range, defender counterattacks (same formula)
   - If either unit reaches 0 HP, emit unit_died(unit) → remove from grid
 3. Play a brief combat flash/shake tween on both units (~0.15 s). No long cutscenes.
 4. After combat, set both units' has_attacked = true.

 Critical files:
 - scripts/battle/CombatResolver.gd

 ---
 [DONE] Phase 5 — Turn Manager & End Conditions

 Goal: Structured player turn → enemy turn loop.

 Steps:
 1. TurnManager.gd (autoload):
   - State machine: PLAYER_TURN → ENEMY_TURN → PLAYER_TURN ...
   - end_player_turn(): reset all player unit flags (has_moved, has_attacked), trigger enemy AI
   - end_enemy_turn(): reset enemy flags, switch back
 2. "End Turn" button in HUD triggers TurnManager.end_player_turn().
 3. Win condition: all enemy units dead → emit battle_won.
 4. Lose condition: all player units dead → emit battle_lost.
 5. Connect signals to show a result screen and return to overworld.

 Critical files:
 - scripts/battle/TurnManager.gd
 - scenes/ui/HUD.tscn

 ---
 [DONE] Phase 6 — Basic Enemy AI

 Goal: Enemies take meaningful, fast actions on their turn.

 Steps:
 1. EnemyAI.gd:
   - For each enemy unit (in order): find the nearest player unit → move as close as possible → attack if in range
   - Use the same AStarGrid2D pathfinding from Phase 1
 2. AI actions run with a short stagger delay (await get_tree().create_timer(0.3).timeout) so the player can follow what happened.
 3. After all enemies act, call TurnManager.end_enemy_turn().

 Critical files:
 - scripts/battle/EnemyAI.gd

 ---
 [DONE] Phase 7 — Overworld Graph

 Goal: A navigable world map connecting battle instances.

 Steps:
 1. OverworldGraph resource: list of OverworldNode resources (id, label, position) + list of edges [id_a, id_b, unlocked].
 2. Overworld.tscn: renders nodes as clickable buttons and edges as Line2D connectors.
 3. Locked edges are drawn greyed out and non-interactive.
 4. Clicking an unlocked node → load its associated BattleMap scene via get_tree().change_scene_to_file().
 5. After winning a battle, return to the overworld and unlock the next edge(s) (stored in a SaveData autoload).

 Critical files:
 - scenes/overworld/Overworld.tscn
 - scripts/overworld/Overworld.gd
 - resources/overworld/WorldGraph.tres

 Phase 9 — Content & Depth (current focus)

 Goal: Make battles more varied and classes feel distinct.

 Steps:
